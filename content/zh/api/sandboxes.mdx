## 需要身份验证

所有 API 请求都需要使用 `X-API-Key` 标头和您的 API 密钥进行身份验证。

## 沙盒状态

沙盒状态指示其当前生命周期状态：

| 状态 | 描述 |
|------|------|
| `created` | 沙盒已创建但未启动 |
| `starting` | 沙盒正在启动，资源正在分配（子状态：allocating、deploying、initializing、waiting_ready） |
| `running` | 沙盒正在运行且可访问 |
| `terminating` | 沙盒正在终止，资源正在清理（子状态：cleaning_resources、cleaning_data） |
| `terminated` | 沙盒已终止，无法重启 |
| `failed` | 沙盒在创建或操作期间遇到错误 |

## API 端点

### 创建沙盒

**POST** `/v1/sandboxes`

创建新的沙盒环境。

**请求参数：**

| 参数 | 类型 | 必需 | 默认值 | 描述 |
|------|------|------|--------|------|
| `name` | string | 否 | 自动生成 | 人类可读的沙盒名称（0-24 个字符，空值将仅使用随机后缀） |
| `description` | string | 否 | 空 | 沙盒用途的详细描述 |
| `template` | string | 否 | "base" | 模板名称或 ID（例如："python-dev" 或 "tpl-abc123"） |
| `project_id` | string | 否 | 用户的默认值 | 要关联沙盒的项目 |
| `cpu_count` | integer | 否 | 模板默认值 | CPU 核心数 |
| `memory_mb` | integer | 否 | 模板默认值 | 内存分配（MB） |
| `storage_gb` | integer | 否 | 计划最大值的 50% | 持久存储（GB）（0 = 使用订阅计划最大值的 50%，向上取整） |
| `timeout` | integer | 否 | 300 | 沙盒超时（秒） |
| `env_vars` | object | 否 | {} | 要在沙盒中设置的环境变量 |
| `metadata` | object | 否 | {} | 沙盒元数据的自定义键值对 |
| `secure` | boolean | 否 | true | 沙盒的安全设置 |
| `allow_internet_access` | boolean | 否 | true | 是否允许从沙盒访问互联网 |
| `object_storage` | object | 否 | null | 用于挂载 S3 兼容存储的对象存储配置 |
| `custom_ports` | array | 否 | [] | 自定义端口配置数组（模板中不存在的端口）。每个端口必须具有 'port'（数字）和 'name'（字符串）。最多 16 个总端口（模板 + 自定义）。 |
| `is_async` | boolean | 否 | false | 为 true 时立即返回；为 false 时等待运行/失败状态 |

**示例请求：**

```bash
curl -X POST https://api.scalebox.dev/v1/sandboxes \
  -H "X-API-Key: sk-1234567890abcdef1234567890abcdef12345678" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "my-dev",
    "template": "python-dev",
    "cpu_count": 2,
    "memory_mb": 4096,
    "storage_gb": 10,
    "timeout": 3600,
    "env_vars": {
      "DEBUG": "true",
      "API_KEY": "your-secret-key"
    },
    "metadata": {
      "project": "web-app",
      "environment": "development"
    },
    "object_storage": {
      "uri": "s3://my-bucket/data",
      "mount_point": "/mnt/oss",
      "access_key": "YOUR_S3_ACCESS_KEY",
      "secret_key": "YOUR_S3_SECRET_KEY",
      "region": "us-east-1"
    },
    "custom_ports": [
      {
        "port": 8080,
        "name": "web-server",
        "protocol": "tcp"
      },
      {
        "port": 9000,
        "name": "api-server",
        "protocol": "tcp"
      }
    ]
  }'
```

| `cpu_count` | integer | 否 | 从基础模板继承 | 使用此模板的沙盒的默认 CPU 核心数（nil/省略 = 继承，0 = 显式继承，>0 = 使用并强制执行最小值） |
| `memory_mb` | integer | 否 | 从基础模板继承 | 使用此模板的沙盒的默认内存（MB）（nil/省略 = 继承，0 = 显式继承，>0 = 使用并强制执行最小值） |

| `custom_command` | string | 否 | - | 模板的自定义启动命令（不从基础模板继承） |
| `ready_command` | string | 否 | - | 模板的就绪检查命令（不从基础模板继承） |

**示例请求：**

```bash

  -H "X-API-Key: sk-1234567890abcdef1234567890abcdef12345678" \
  -H "Content-Type: application/json" \
  -d '{

    "description": "从我的运行沙盒创建的模板",

    "memory_mb": 8192,
```

## 对象存储

ScaleBox 支持使用 FUSE 将 S3 兼容的对象存储挂载到沙盒中。您可以在沙盒创建时配置对象存储，或在运行时手动挂载。所有沙盒默认都启用了 FUSE 功能。

### 对象存储配置

创建沙盒时，您可以提供具有以下字段的 `object_storage` 对象：

| 字段 | 类型 | 必需 | 描述 |
|------|------|------|------|
| `uri` | string | 是 | S3 兼容存储 URI，格式：`s3://bucket-name/path` 或 `oss://bucket-name/path` |
| `mount_point` | string | 是 | 容器中存储将挂载到的绝对路径 |
| `access_key` | string | 是 | S3 访问密钥 ID。凭据永远不会存储在数据库中或在 API 响应中返回。 |
| `secret_key` | string | 是 | S3 秘密访问密钥。凭据永远不会存储在数据库中或在 API 响应中返回。 |
| `region` | string | 可选 | AWS 区域名称（例如，`us-east-1`、`ap-east-1`）。必须提供 `region` 或 `endpoint` 中的至少一个。 |
| `endpoint` | string | 可选 | 自定义 S3 兼容端点 URL。必须提供 `region` 或 `endpoint` 中的至少一个。 |

### 自动挂载

如果在创建时配置了对象存储，它将在沙盒启动时自动挂载。挂载脚本在主应用程序之前运行，确保存储立即可用。

### 运行时手动挂载

所有沙盒都启用了 FUSE 功能（`SYS_ADMIN` 功能和 `/dev/fuse` 设备）。您可以随时通过在运行中的容器中执行命令手动挂载对象存储：

```bash
# 创建凭证文件
echo "ACCESS_KEY:SECRET_KEY" > /root/.s3fs-credentials
chmod 600 /root/.s3fs-credentials

# 创建挂载点
mkdir -p /mnt/oss

# 挂载 S3 存储桶（对于非默认区域，需要同时指定 url 和 endpoint）
s3fs bucket-name:/path /mnt/oss \
  -o passwd_file=/root/.s3fs-credentials \
  -o url=https://s3.region.amazonaws.com \
  -o endpoint=region
```

**安全注意：** 对象存储凭据永远不会持久化到数据库中。只有 URI 和挂载点会被存储并在 API 响应中返回。凭据仅在挂载操作期间使用。

## 指标 API

沙盒指标 API 提供实时性能数据和历史趋势，用于监控资源利用率。提供两个端点：用于 API 使用者的原始指标和用于前端可视化的图表优化数据。

### 指标端点

#### 原始指标：`/v1/sandboxes/{sandbox_id}/metrics`

返回标准化的时间序列指标，格式针对 API 使用者和数据处理进行了优化。

- **数据格式：** 带时间戳的指标数组，包含 CPU、内存和磁盘使用情况
- **时间范围：** 可配置的开始/结束时间，具有可自定义的步长间隔
- **用例：** 监控、告警、数据分析、与外部工具集成
- **响应大小：** 紧凑，最少的元数据

#### 图表指标：`/v1/sandboxes/{sandbox_id}/metrics/chart`

返回针对前端可视化优化的图表就绪数据，包含元数据、统计信息和样式。

- **数据格式：** 结构化图表配置，包含时间序列数据和元数据
- **功能：** 内置统计信息、趋势分析、配色方案和图表配置
- **用例：** 仪表板小部件、实时监控、性能分析
- **响应大小：** 较大，包括图表配置和统计信息

### 选择正确的端点

**在以下情况下使用原始指标：**
- 构建自定义仪表板
- 与外部监控工具集成
- 处理数据分析数据
- 最小化响应负载大小

**在以下情况下使用图表指标：**
- 构建前端可视化
- 需要内置统计信息和趋势
- 想要预配置的图表样式
- 构建实时监控小部件

### 时间参数

两个指标端点都支持灵活的时间范围配置：

| 参数 | 描述 | 示例 |
|------|------|------|
| `start` | 指标查询的开始时间。支持 ISO 8601、RFC3339 和 Unix 时间戳格式 | "2024-01-15T10:00:00Z", "1705312800" |
| `end` | 指标查询的结束时间。如果未指定，默认为当前时间 | "2024-01-15T10:30:00Z", "now" |
| `step` | 数据点之间的时间间隔。原始指标：秒（整数），图表指标：持续时间字符串或秒 | "30", "15m", "1h", "5s" |

### 指标数据结构

指标 API 提供全面的资源利用率数据：

**资源指标：**
- **CPU：** 请求的核心数（整数）和使用百分比（0-100）
- **内存：** 请求和使用的内存（字节，int64）
- **存储：** 请求和使用的磁盘空间（字节，int64）
- **运行时间：** 沙盒运行时间（秒，int64）

**数据格式：**
- **时间戳：** ISO 8601 格式（例如，"2024-01-15T10:30:00Z"）
- **CPU 使用率：** 请求的 CPU 核心的百分比（0.0 - 100.0）
- **内存/存储：** 作为 64 位整数的字节
- **时间窗口：** 图表端点的 Unix 毫秒，原始指标的 ISO 字符串

### 智能查询优化

API 根据沙盒生命周期和数据可用性自动优化查询：

- **自动时间范围调整：** 查询会自动调整，仅获取沙盒实际运行期间的数据
- **步长优化：** 根据查询时间范围智能调整步长间隔，以提供最佳数据分辨率
- **数据可用性处理：** 优雅地处理指标数据不可用或沙盒未运行的情况

### 错误处理

指标 API 提供清晰的错误响应并优雅地处理边缘情况：

- **无可用数据：** 当沙盒未运行或指标不可用时，返回空指标数组和状态
- **无效时间范围：** 如果开始/结束时间顺序错误，自动交换它们
- **资源未找到：** 如果沙盒不存在或用户缺乏访问权限，返回 404

### 最佳实践

遵循以下指南以获得最佳指标 API 使用：

- **时间范围选择：** 使用适当的步长：实时监控 5-30 秒，历史分析 1-15 分钟
- **数据轮询：** 实时仪表板每 30-60 秒轮询一次指标，避免过多请求
- **错误处理：** 始终检查响应状态并处理指标数据不可用的情况
