<Callout type="warn">
**需要身份驗證：** API 金鑰管理端點需要已驗證請求。可使用 `X-API-Key`、`Authorization: Api-Key ...` 或支援的 Bearer Token。
</Callout>

<Callout type="info">
**密鑰顯示規則：** 完整的 `api_key` 只會在建立與取得單一金鑰時回傳；列表與更新回應只會顯示前綴。
</Callout>

## 標準回應格式

API 金鑰端點使用標準信封格式：

```json
{
  "success": true,
  "data": {},
  "timestamp": "2026-04-17T12:34:56Z"
}
```

刪除操作會回傳只有 `message` 的成功回應。

## API 端點

### 建立 API 金鑰

`POST /v1/api-keys`

**請求主體**

| 名稱 | 型別 | 必填 | 說明 |
|------|------|------|------|
| name | string | 是 | API 金鑰名稱 |
| description | string | 否 | 人類可讀的用途說明 |

**回應**

```json
{
  "success": true,
  "data": {
    "key_id": "key-abc123def456789",
    "name": "development-key",
    "description": "API key for local development",
    "api_key": "sk-1234567890abcdef1234567890abcdef12345678",
    "prefix": "sk-1234",
    "is_active": true,
    "created_at": "2026-04-17T12:00:00Z",
    "owner": {
      "user_id": "usr-xyz789abc123456",
      "username": "developer",
      "display_name": "John Developer",
      "email": "john@example.com"
    }
  },
  "timestamp": "2026-04-17T12:00:00Z"
}
```

### 列出 API 金鑰

`GET /v1/api-keys`

**查詢參數**

| 名稱 | 型別 | 必填 | 說明 |
|------|------|------|------|
| page | integer | 否 | 分頁頁碼，預設 `1` |
| limit | integer | 否 | 每頁回傳筆數；別名：`page_size` |
| offset | integer | 否 | 要略過的筆數；別名：`skip` |
| user_id | string | 否 | 僅 root 使用者可用：依擁有者使用者 ID 篩選 |
| status | string | 否 | `active` 或 `inactive` |
| search | string | 否 | 名稱子字串搜尋 |
| sort_by | string | 否 | 排序欄位 |
| sort_order | string | 否 | `asc` 或 `desc` |

**回應**

```json
{
  "success": true,
  "data": {
    "api_keys": [
      {
        "key_id": "key-abc123def456789",
        "name": "development-key",
        "description": "API key for local development",
        "prefix": "sk-1234567",
        "is_active": true,
        "last_used_at": "2026-04-17T11:45:00Z",
        "created_at": "2026-04-10T10:00:00Z",
        "updated_at": "2026-04-17T11:45:00Z",
        "owner": {
          "user_id": "usr-xyz789abc123456",
          "username": "developer",
          "display_name": "John Developer",
          "email": "john@example.com"
        }
      }
    ],
    "pagination": {
      "page": 1,
      "limit": 20,
      "offset": 0,
      "total": 1,
      "total_pages": 1
    }
  },
  "timestamp": "2026-04-17T12:00:00Z"
}
```

### 更新 API 金鑰

`PUT /v1/api-keys/{key_id}`

**請求主體**

| 名稱 | 型別 | 必填 | 說明 |
|------|------|------|------|
| name | string | 否 | 新金鑰名稱 |
| description | string | 否 | 新描述 |

**回應**

```json
{
  "success": true,
  "data": {
    "key_id": "key-abc123def456789",
    "name": "production-key",
    "description": "Updated API key for production use",
    "prefix": "sk-1234567",
    "is_active": true,
    "last_used_at": "2026-04-17T11:45:00Z",
    "created_at": "2026-04-10T10:00:00Z",
    "updated_at": "2026-04-17T12:05:00Z"
  },
  "timestamp": "2026-04-17T12:05:00Z"
}
```

### 更新 API 金鑰狀態

`PUT /v1/api-keys/{key_id}/status`

**請求主體**

| 名稱 | 型別 | 必填 | 說明 |
|------|------|------|------|
| is_active | boolean | 是 | `true` 啟用，`false` 停用 |

**回應**

```json
{
  "success": true,
  "data": {
    "message": "API key disabled successfully",
    "is_active": false
  },
  "timestamp": "2026-04-17T12:06:00Z"
}
```

### 刪除 API 金鑰

`DELETE /v1/api-keys/{key_id}`

**回應**

```json
{
  "success": true,
  "message": "API key deleted successfully",
  "timestamp": "2026-04-17T12:07:00Z"
}
```

## 驗證與限制

- API 金鑰名稱會套用後端的嚴格驗證規則。
- 重複名稱會回傳 `409 Conflict`。
- Admin 使用者只能擁有一把 API 金鑰。
- 非 admin 使用者最多可擁有五把 API 金鑰。
- 建立回應的 `prefix` 比 list/get/update 範例更短，這是目前後端的實際行為。

## 常見錯誤

```json
{
  "success": false,
  "error": "An API key with this name already exists for your account",
  "timestamp": "2026-04-17T12:10:00Z"
}
```

- `400`：請求主體無效、金鑰名稱無效，或已達金鑰數量上限
- `401`：身份驗證遺失或無效
- `404`：在目前可見範圍內找不到金鑰
- `409`：金鑰名稱重複
- `500`：資料庫或金鑰產生流程失敗
