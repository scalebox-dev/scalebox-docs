## 需要認證

所有 API 請求都需要使用 `X-API-Key` 請求頭和您的 API 密鑰進行認證。

## Webhook 概念

Webhook 是 HTTP 回調，當 ScaleBox 中發生事件時會通知您的應用程序。無需持續輪詢 API 來檢查狀態變化，Webhook 會自動將事件推送到您的端點。

### Webhook 工作原理

1. **事件發生** - 沙盒啟動、終止或賬戶中發生其他事件
2. **Webhook 檢測** - ScaleBox 檢測到事件並找到匹配的 Webhook 端點（5 秒內）
3. **HTTP POST 交付** - ScaleBox 向您的 Webhook URL 發送包含事件數據的 HTTP POST 請求
4. **您的端點響應** - 您的端點處理 Webhook 並返回 HTTP 200 OK（失敗時重試）

### Webhook 的優勢

- **減少 API 調用：** 無需輪詢 - 事件自動推送（API 調用減少 99%+）
- **實時通知：** 事件發生後 5 秒內接收通知
- **事件驅動架構：** 完美適用於自動化、CI/CD 管道和 AI 代理
- **自動重試：** 失敗的交付會自動重試，採用指數退避策略

## API 端點

### 創建 Webhook

**POST** `/v1/webhooks`

創建新的 Webhook 端點以接收事件通知。

#### 請求參數

| 參數 | 類型 | 必需 | 默認值 | 描述 |
|------|------|------|--------|------|
| `url` | string | 是 | - | 接收 Webhook 的 HTTPS URL |
| `event_types` | array[string] | 是 | - | 要訂閱的事件類型數組（例如：['sandbox.started', 'sandbox.terminated']） |
| `description` | string | 否 | - | Webhook 端點的可選描述 |

#### 請求示例

```bash
curl -X POST https://api.scalebox.dev/v1/webhooks \
  -H "X-API-Key: sk-1234567890abcdef1234567890abcdef12345678" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://your-app.com/webhooks/scalebox",
    "event_types": ["sandbox.started", "sandbox.terminated"],
    "description": "生產環境沙盒生命週期事件 Webhook"
  }'
```

#### 響應示例

```json
{
  "success": true,
  "data": {
    "endpoint_id": "whk-abc123def456789",
    "url": "https://your-app.com/webhooks/scalebox",
    "event_types": ["sandbox.started", "sandbox.terminated"],
    "is_active": true,
    "description": "生產環境沙盒生命週期事件 Webhook",
    "timeout_seconds": 30,
    "max_retries": 3,
    "created_at": "2024-01-15T10:30:00Z",
    "updated_at": "2024-01-15T10:30:00Z"
  }
}
```

### 更新 Webhook

**PUT** `/v1/webhooks/{endpoint_id}`

更新 Webhook 端點配置（URL、事件類型、狀態）。

#### 請求參數

| 參數 | 類型 | 必需 | 默認值 | 描述 |
|------|------|------|--------|------|
| `url` | string | 否 | - | 新的 Webhook 交付 URL |
| `event_types` | array[string] | 否 | - | 更新的訂閱事件類型列表 |
| `is_active` | boolean | 否 | - | 啟用或禁用 Webhook 端點 |
| `description` | string | 否 | - | 更新的描述 |
| `timeout_seconds` | integer | 否 | 30 | HTTP 請求超時時間（5-300 秒） |
| `max_retries` | integer | 否 | 3 | 最大重試次數（0-10） |

#### 請求示例

```bash
curl -X PUT https://api.scalebox.dev/v1/webhooks/whk-abc123def456789 \
  -H "X-API-Key: sk-1234567890abcdef1234567890abcdef12345678" \
  -H "Content-Type: application/json" \
  -d '{
    "is_active": false,
    "event_types": ["sandbox.started", "sandbox.terminated", "sandbox.failed"]
  }'
```

## 事件類型

ScaleBox 發出各種事件類型，您可以通過 Webhook 訂閱：

| 事件類型 | 描述 |
|---------|------|
| `sandbox.created` | 沙盒創建時觸發（尚未運行） |
| `sandbox.started` | 沙盒開始運行並準備就緒時觸發 |
| `sandbox.stopped` | 沙盒停止時觸發（退出運行狀態） |
| `sandbox.paused` | 沙盒暫停時觸發（CPU/內存計費停止） |
| `sandbox.resumed` | 沙盒恢復時觸發（CPU/內存計費恢復） |
| `sandbox.terminated` | 沙盒完全終止並清理時觸發 |
| `sandbox.failed` | 沙盒啟動失敗或崩潰時觸發 |
| `template.uploaded` | 模板鏡像上傳到 Harbor 時觸發 |
| `template.deleted` | 模板刪除時觸發 |

## Webhook 負載

所有 Webhook 交付都包含一致的 JSON 負載結構：

```json
{
  "id": "evt-abc123def456789",
  "type": "sandbox.started",
  "timestamp": "2024-01-15T10:30:00Z",
  "data": {
    "sandbox_id": "sbx-xyz789abc123456",
    "status": "running",
    "cpu_count": 2,
    "memory_mb": 4096,
    "storage_gb": 20,
    "template_id": "tpl-python-3.11",
    "project_id": "prj-abc123def456789",
    "owner_user_id": "usr-xyz789abc123456",
    "owner_account_id": "acc-123456789",
    "kubernetes_metadata": {
      "cluster_id": "cls-abc123",
      "namespace_id": "ns-xyz789",
      "pod_name": "sbx-xyz789abc123456",
      "pod_ip": "10.0.0.5",
      "node_name": "worker-node-1"
    }
  }
}
```

### 負載字段

- `id` - 唯一事件標識符 (evt-xxxxx)
- `type` - 事件類型（例如："sandbox.started"）
- `timestamp` - 事件發生時的 ISO 8601 時間戳
- `data` - 特定於事件的數據對象（因事件類型而異）

## 安全與驗證

所有 Webhook 交付都包含 HMAC-SHA256 簽名，您可以使用它來驗證請求的真實性。這可以防止篡改並確保 Webhook 來自 ScaleBox。

### HTTP 請求頭

- `X-ScaleBox-Signature` - 負載的 HMAC-SHA256 簽名
- `X-ScaleBox-Event-Type` - 事件類型（例如："sandbox.started"）
- `X-ScaleBox-Event-ID` - 唯一事件標識符
- `Content-Type` - application/json
- `User-Agent` - ScaleBox-Webhooks/1.0

### 簽名驗證示例

**Python:**

```python
import hmac
import hashlib

def verify_webhook_signature(payload_body, signature_header, secret):
    """驗證 Webhook 簽名"""
    expected_signature = hmac.new(
        secret.encode('utf-8'),
        payload_body.encode('utf-8'),
        hashlib.sha256
    ).hexdigest()
    
    received_signature = signature_header.replace('sha256=', '')
    return hmac.compare_digest(expected_signature, received_signature)
```

**Node.js:**

```javascript
const crypto = require('crypto');

function verifyWebhookSignature(payloadBody, signatureHeader, secret) {
  const expectedSignature = crypto
    .createHmac('sha256', secret)
    .update(payloadBody)
    .digest('hex');
  
  const receivedSignature = signatureHeader.replace('sha256=', '');
  return crypto.timingSafeEqual(
    Buffer.from(expectedSignature),
    Buffer.from(receivedSignature)
  );
}
```

> **重要：** Webhook 密鑰在創建端點時生成，永遠不會在 API 響應中暴露。您必須安全地存儲此密鑰以驗證傳入的 Webhook。如果丟失密鑰，您需要刪除並重新創建 Webhook 端點。

## 重試機制

ScaleBox 自動重試失敗的 Webhook 交付以確保可靠性。失敗的交付會使用指數退避策略進行重試。

### 重試行為

- **自動重試：** 失敗的交付（非 2xx HTTP 狀態碼）會自動重試
- **指數退避：** 重試間隔：2 分鐘、4 分鐘、6 分鐘（可配置倍數）
- **最大嘗試次數：** 默認：3 次嘗試（每個端點可配置，0-10）
- **交付狀態：** `pending` → `retrying` → `delivered` 或 `failed`

## 最佳實踐

### 使用 HTTPS URL
始終使用 HTTPS 作為 Webhook 端點以確保安全交付。

### 驗證簽名
始終驗證 X-ScaleBox-Signature 請求頭以確保 Webhook 的真實性。

### 快速響應
在 30 秒內返回 HTTP 200 OK 以避免超時。

### 冪等處理
使用事件 ID 防止在 Webhook 重試時重複處理。

### 監控交付歷史
定期檢查交付歷史以識別和修復端點問題。

## HTTP 狀態碼

API 返回的標準 HTTP 狀態碼：

| 代碼 | 描述 |
|------|------|
| 200 | 成功 |
| 201 | 已創建 |
| 400 | 錯誤請求 |
| 401 | 未授權 |
| 403 | 禁止訪問 |
| 404 | 未找到 |
| 500 | 服務器內部錯誤 |
