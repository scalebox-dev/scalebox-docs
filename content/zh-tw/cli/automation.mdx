在非互動式腳本、排程工作與 CI 管線中使用 ScaleBox CLI。本頁聚焦真正適合自動化的重點：API 金鑰驗證、機器可讀輸出、分頁處理，以及非同步生命週期輪詢。

> 在腳本中優先使用 `auth login --api-key`、`-o json` 或 `-o json-compact`、明確的分頁參數，以及 `--async` 搭配輪詢來處理較長的沙盒操作。

## 以非互動方式驗證

瀏覽器登入適合人工操作，但自動化流程應改用 API 金鑰。請透過 CI 系統提供環境變數，不要把密鑰硬編碼進腳本。

```bash
export SCALEBOX_SERVER_URL="https://api.scalebox.dev"
export SCALEBOX_API_KEY="sk-your-api-key"

scalebox-cli auth login \
  --api-key "$SCALEBOX_API_KEY" \
  --server-url "$SCALEBOX_SERVER_URL"
```

## 選擇機器可讀輸出

在自動化場景中不要依賴人類可讀的表格輸出。使用 `-o json` 取得較易讀的日誌，或使用 `-o json-compact` 進行管線處理。您也可以透過 `SCALEBOX_OUTPUT` 設定預設值。

```bash
export SCALEBOX_OUTPUT=json-compact

scalebox-cli template list --page 1 --limit 10
scalebox-cli sandbox list --page 1 --limit 20
```

## 明確處理分頁

像 `template list` 與 `sandbox list` 這類高頻清單命令支援 `--page`、`--limit`、`--all` 與 `--max-items`。在自動化中請明確選擇一種模式：

- 需要固定頁面時，用 `--page` 搭配 `--limit`。
- 需要遍歷完整結果集時，用 `--all`。
- 需要限制執行時間或輸出量時，加上 `--max-items`。

```bash
# 儀表板或稽核工作只取單頁
scalebox-cli -o json template list --page 2 --limit 10

# 夜間同步工作遍歷全部結果
scalebox-cli -o json-compact sandbox list --all --max-items 200
```

## 用非同步建立並主動輪詢狀態

對於耗時較長的沙盒操作，建議使用非同步模式並顯式輪詢。這樣腳本邏輯更穩定，也不會假設建立、暫停或恢復會立刻完成。

```bash
SANDBOX_ID="$(scalebox-cli -o json-compact sandbox create \
  --template tpl-abc123 \
  --name ci-job \
  --async | jq -r '.data.sandbox.id')"

until [ "$(scalebox-cli -o json-compact sandbox get "$SANDBOX_ID" | jq -r '.data.sandbox.status')" = "running" ]; do
  sleep 5
done

scalebox-cli sandbox exec "$SANDBOX_ID" -- echo "ready"
```

## 實用腳本慣例

- 在 shell 腳本中啟用 `set -euo pipefail`。
- 需要串接處理時優先使用 `json-compact`，再搭配 `jq` 等解析器。
- 若腳本不應開啟互動式終端機，請在同步建立路徑上使用 `--no-terminal`。
- 並非每個清單命令都使用同一組分頁參數，撰寫自動化前請先查看該命令的 `--help`。
