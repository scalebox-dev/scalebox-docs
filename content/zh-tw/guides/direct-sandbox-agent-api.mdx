<Callout type="info">
當你想在沙箱建立完成後，直接與**執行中的沙箱**互動時，請使用本指南。後端仍然是沙箱生命週期與中繼資料的控制平面，而 sandbox agent 則是暴露在 sandbox domain 上的執行期 API。
</Callout>

<Callout type="warn">
只要條件允許，我們都強烈建議你優先使用官方 **Python**、**Go** 或 **JavaScript** SDK 進行正式整合。它們已經封裝了 sandbox-domain 驗證、ConnectRPC 呼叫模式、串流處理與錯誤處理。raw sandbox-agent HTTP 或 ConnectRPC 呼叫更適合作為進階、底層路徑使用。
</Callout>

官方 SDK 直接連結：

- [Python SDK 倉庫](https://github.com/scalebox-dev/scalebox-sdk-python)
- [JavaScript SDK 倉庫](https://github.com/scalebox-dev/scalebox-sdk-js)
- [Go SDK 倉庫](https://github.com/scalebox-dev/scalebox-sdk-golang)

## 這條路徑是什麼

當你透過 ScaleBox 後端建立或查詢沙箱後，回應中可能包含：

- `sandbox_domain` - 沙箱的直接執行期網域
- `envd_access_token` - 為該沙箱產生的沙箱級存取權杖

這個 `envd_access_token` 就是 sandbox agent 期望接收的 `X-Access-Token` header 值。對 direct agent call 而言，`Authorization` header 目前固定為 `Bearer root`。

CLI 與各類 SDK 在許多沙箱內操作中，走的也是這條直接執行期路徑。

## 什麼時候使用

當你需要以下能力時，適合直接呼叫 sandbox-agent API：

- 直接對 sandbox domain 進行檔案上傳與下載
- 不經過後端，直接進行程序與 PTY 控制
- 在相容模板上執行程式碼與執行上下文相關流程
- 建立更貼近沙箱執行期本身的整合

當你需要建立、列表、查詢、暫停、恢復、終止、模板、專案、用量、計費等控制平面操作時，仍應使用後端 API。

## 前置條件

1. 先透過後端 API、CLI 或 SDK 建立或查詢一個沙箱。
2. 從沙箱物件中讀取 `sandbox_domain`。
3. 從同一個沙箱物件中讀取 `envd_access_token`。

後端回傳的相關欄位範例：

```json
{
  "sandbox_id": "sbx-abc123def456789",
  "sandbox_domain": "sbx-abc123def456789.example.scalebox.dev",
  "envd_access_token": "envd-abc123def456789"
}
```

## 基礎 URL 與認證

進行 direct call 時，直接把 sandbox domain 當成主機名稱：

```bash
export SANDBOX_DOMAIN="sbx-abc123def456789.example.scalebox.dev"
export ENVD_ACCESS_TOKEN="envd-abc123def456789"
```

對大多數 sandbox-agent 請求，送出以下 headers：

```http
Authorization: Bearer root
X-Access-Token: <envd_access_token>
```

範例：

```bash
curl -X GET "https://${SANDBOX_DOMAIN}/health"
```

```bash
curl -X POST "https://${SANDBOX_DOMAIN}/sandboxagent.ContextService/CreateContext" \
  -H "Authorization: Bearer root" \
  -H "X-Access-Token: ${ENVD_ACCESS_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"language":"python","cwd":"/home/user"}'
```

## 認證模型

這裡有兩種認證方式：

| 路徑類型 | 認證方式 | 說明 |
|---|---|---|
| 大多數 sandbox-agent 端點 | `Authorization: Bearer root` + `X-Access-Token` | ConnectRPC procedure 與一般 HTTP 端點的標準直連方式 |
| `/upload` 與 `/download/...` | 相同 headers，或簽名 URL 查詢參數 | 適合具有時效性的委派式檔案存取 |

對多數使用者而言，直接使用 header 認證是最簡單的方式。

## 端點總覽

目前 raw sandbox-agent 對外暴露 **22 個可透過 HTTP 呼叫的端點**：

- **3 個一般 HTTP 端點**
- **19 個 ConnectRPC procedure 端點**

### 一般 HTTP 端點

| Method | Path | Auth | 說明 |
|---|---|---|---|
| `GET` | `/health` | 無 | 簡單健康檢查，回傳 `OK` |
| `POST` | `/upload` | headers 或 signed URL | multipart 上傳端點 |
| `GET` | `/download/{path}` | headers 或 signed URL | 檔案下載端點，支援 Range |

### ConnectRPC 端點

其餘端點都是 procedure 風格的 HTTP 路徑。Unary procedure 可以透過 HTTP `POST` + JSON 呼叫。Streaming procedure 更適合透過 CLI、SDK 或 ConnectRPC 客戶端呼叫。

#### Filesystem 服務

| Procedure path | 類型 | 用途 |
|---|---|---|
| `/sandboxagent.Filesystem/Stat` | unary | 查詢檔案或目錄資訊 |
| `/sandboxagent.Filesystem/MakeDir` | unary | 建立目錄 |
| `/sandboxagent.Filesystem/Move` | unary | 移動或重新命名路徑 |
| `/sandboxagent.Filesystem/ListDir` | unary | 列出目錄內容 |
| `/sandboxagent.Filesystem/Remove` | unary | 刪除檔案或目錄 |
| `/sandboxagent.Filesystem/CreateWatcher` | unary | 建立 watcher 並回傳 `watcher_id` |
| `/sandboxagent.Filesystem/GetWatcherEvents` | unary | 輪詢 watcher 事件 |
| `/sandboxagent.Filesystem/RemoveWatcher` | unary | 刪除 watcher |
| `/sandboxagent.Filesystem/WatchDir` | server stream | 直接串流接收檔案系統事件 |

#### Process 服務

| Procedure path | 類型 | 用途 |
|---|---|---|
| `/sandboxagent.Process/List` | unary | 列出已追蹤的程序 |
| `/sandboxagent.Process/Connect` | server stream | 連接到既有程序或 PTY |
| `/sandboxagent.Process/Start` | server stream | 啟動程序並串流接收輸出 |
| `/sandboxagent.Process/Update` | unary | 更新程序狀態，例如 PTY 尺寸 |
| `/sandboxagent.Process/StreamInput` | client stream | 串流送出 stdin 或 PTY 輸入 |
| `/sandboxagent.Process/SendInput` | unary | 傳送一次輸入 |
| `/sandboxagent.Process/SendSignal` | unary | 傳送 `SIGTERM` 或 `SIGKILL` |

#### Execution 與 Context 服務

| Procedure path | 類型 | 用途 |
|---|---|---|
| `/sandboxagent.ExecutionService/Execute` | server stream | 執行程式碼並串流回傳輸出與結果 |
| `/sandboxagent.ContextService/CreateContext` | unary | 建立執行上下文 |
| `/sandboxagent.ContextService/DestroyContext` | unary | 銷毀執行上下文 |

## 一般 HTTP 範例

### 健康檢查

```bash
curl "https://${SANDBOX_DOMAIN}/health"
```

### 上傳檔案

上傳端點要求 `multipart/form-data`，並包含：

- 一個 `file` part
- 一個 `path` 表單欄位，表示目標路徑

```bash
curl -X POST "https://${SANDBOX_DOMAIN}/upload" \
  -H "Authorization: Bearer root" \
  -H "X-Access-Token: ${ENVD_ACCESS_TOKEN}" \
  -F "file=@./script.py" \
  -F "path=/tmp/script.py"
```

### 下載檔案

```bash
curl -L "https://${SANDBOX_DOMAIN}/download/tmp/script.py" \
  -H "Authorization: Bearer root" \
  -H "X-Access-Token: ${ENVD_ACCESS_TOKEN}" \
  -o ./script.py
```

下載端點也支援 `Range` 請求，適合斷點續傳或部分下載。

## Unary ConnectRPC 範例

### 建立執行上下文

```bash
curl -X POST "https://${SANDBOX_DOMAIN}/sandboxagent.ContextService/CreateContext" \
  -H "Authorization: Bearer root" \
  -H "X-Access-Token: ${ENVD_ACCESS_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "language": "python",
    "cwd": "/home/user"
  }'
```

### 列出目錄

```bash
curl -X POST "https://${SANDBOX_DOMAIN}/sandboxagent.Filesystem/ListDir" \
  -H "Authorization: Bearer root" \
  -H "X-Access-Token: ${ENVD_ACCESS_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "path": "/tmp",
    "depth": 1
  }'
```

### 查詢路徑資訊

```bash
curl -X POST "https://${SANDBOX_DOMAIN}/sandboxagent.Filesystem/Stat" \
  -H "Authorization: Bearer root" \
  -H "X-Access-Token: ${ENVD_ACCESS_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "path": "/tmp/script.py"
  }'
```

## Streaming procedure

以下執行期操作是串流式的：

- `Filesystem/WatchDir`
- `Process/Connect`
- `Process/Start`
- `Process/StreamInput`
- `ExecutionService/Execute`

這些介面仍然是 HTTP 可呼叫的，但通常更適合透過以下方式使用：

- `scalebox-cli`
- 官方 SDK
- 你自己的 ConnectRPC 客戶端程式

如果你的目標是終端互動、檔案監聽、即時程序輸出或串流程式碼執行，CLI 或 SDK 通常會是更好的介面。

## Signed URL 檔案存取

`/upload` 與 `/download/...` 也支援使用簽名查詢參數，而不是直接傳遞認證 headers。這適合做暫時、受限的檔案存取授權。

但對大多數整合而言，直接使用 header 認證仍然更簡單，也更容易理解。

## 它與 SDK 的關係

SDK 本質上封裝的就是同一條執行期路徑：

- 從後端沙箱回應中讀取 `sandbox_domain` 與 `envd_access_token`
- 設定 `Authorization: Bearer root`
- 設定 `X-Access-Token: <envd_access_token>`
- 呼叫本文展示的同一批 sandbox-domain 端點

這代表你可以先使用 SDK，之後在需要更底層控制時再切換到 raw HTTP。
