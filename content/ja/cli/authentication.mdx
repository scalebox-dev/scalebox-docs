テンプレート、サンドボックス、およびプロジェクトに安全にアクセスするために、API キーを使用して ScaleBox CLI を認証する方法を学びます。 CLI は、環境変数、コマンド フラグ、対話型プロンプトなどの複数の認証方法をサポートしています。

<Callout type="warn">
**🔒 安全な認証情報ストレージ**

CLI は、適切なファイル権限を持つ `~/.scalebox-cli/config.json` に資格情報を安全に保存します。資格情報は、暗号化されていない接続経由で送信されることはありません。
</Callout>

## API キーの種類

ScaleBox は、認証に API キーを使用します。キーの種類が異なると、アクセスのレベルも異なります。

### ユーザー API キー

**形式:** `sk-abc123def456...`

**使用方法:** 通常のユーザー操作と テンプレート 管理

**権限:**
- ✅ パブリック テンプレート を読み取ります
- ✅ 自分の テンプレート を管理
- ✅ サンドボックス を作成する
- ✅ 独自のリソースを表示する

完全なシークレットは、キーの作成時に 1 回だけ返されます。 ScaleBox は、ハッシュと表示プレフィックスをサーバー側に保存します。

## 認証方法

ScaleBox CLI は、自動フォールバックを備えた複数の認証方法をサポートしています。

### 1. ブラウザベースの認証（推奨）

```bash
scalebox-cli auth login
```

最も簡単な認証方法!コマンドを実行するだけで、安全な認証のためにブラウザが自動的に開きます。

- **ルート ユーザー:** ScaleBox アカウントの資格情報を使用してサインインします。
- **組織メンバー:** 専用のサインイン トークンを使用してください
- **OAuth サポート:** GitHub または Google で認証します
- **CLI トークン:** ブラウザーのログインでは、専用の `sb-cli-...` 資格情報 (ダッシュボードの API キーとは別) が発行され、アクティブなプロファイルに保存されます。
- **手動 API キー:** コンソールで作成したキーを使用する場合は、`--api-key sk-...` または `-i` を使用してください。

<Callout type="info">
`--no-browser` を使用してブラウザ認証をスキップし、他の方法にフォールバックします。ブラウザーにログインすると、アクティブなプロファイルの CLI トークンが更新されます。 `--profile` を使用して、別のプロファイル スロットをターゲットにします。コンソール API キー シークレットは、作成時に 1 回だけ表示されます。
</Callout>

### 2. 環境変数

```bash
SCALEBOX_API_KEY=sk-your-api-key scalebox-cli auth login
```

サーバー URL はオプションで、デフォルトは `https://api.scalebox.dev` です。

### 3. コマンドラインフラグ

```bash
scalebox-cli auth login --api-key sk-1234567890abcdef1234567890abcdef12345678 --server-url https://api.scalebox.dev
```

環境変数をオーバーライドする必要がある場合、または自動化スクリプトにフラグを使用します。

### 4. インタラクティブモード

```bash
scalebox-cli auth login -i
```

CLI は、スマートなデフォルトを使用して、API キー (隠し入力) とサーバー URL を安全に要求します。

## 認証コマンド

すべての認証関連コマンドの完全なリファレンス:

### 認証ログイン

ブラウザベースの認証 (デフォルト) または API キーを使用して、ScaleBox で認証します。

**フラグ:**

|旗 |タイプ |説明 |
|------|------|-------------|
| `--api-key` |文字列 | ScaleBox API キー (ブラウザ認証をスキップします) |
| `--server-url` |文字列 | ScaleBox サーバー URL (デフォルト: https://api.scalebox.dev) |
| `-i, --interactive` |ブール値 |対話型モード: API キーとサーバーのプロンプト URL |
| `--no-browser` |ブール値 |ブラウザベースの認証を無効にする |

**例:**
```bash
scalebox-cli auth login --api-key sk-your-key --server-url https://api.scalebox.dev
```

### 認証済み

現在の認証ステータスを確認します。

**例:**
```bash
scalebox-cli auth whoami
```

### 認証ログアウト

アクティブなプロファイルに保存されている認証資格情報を削除します。他のプロファイルが残っている場合、CLI は自動的に別のプロファイルに切り替わります。

**例:**
```bash
scalebox-cli auth logout
```

## 複数のプロファイル

CLI は、1 つの `~/.scalebox-cli/config.json` で複数の名前付き資格情報プロファイルをサポートします。プロファイルを明示的に選択しない場合、コマンドは `current_profile` を使用します。

### 資格情報を名前付きプロファイルに保存する

```bash
scalebox-cli auth login --profile staging --api-key sk-your-key --server-url https://api.scalebox.dev
```

### プロファイルの検査と切り替え

```bash
scalebox-cli auth profile list
scalebox-cli auth profile use prod
scalebox-cli auth profile remove old-staging
```

### 構成を確認し、アクティブなプロファイルを上書きします

```bash
scalebox-cli auth config
scalebox-cli --profile prod sandbox list
```

プロファイル解決の順序は、ルート `--profile`、次に `SCALEBOX_PROFILE`、次に `current_profile` です。

## 認証情報のストレージ

CLI が認証資格情報を保存および管理する方法を理解します。

### 📁 保管場所

- **Linux/macOS:** `~/.scalebox-cli/config.json`
- **Windows:** `%USERPROFILE%\.scalebox-cli\config.json`

### 🔒 ファイルのアクセス許可

- 構成ファイルは `0600` 権限で作成されます (所有者は読み取り/書き込みのみ)
- ディレクトリは `0700` 権限で作成されます (所有者アクセスのみ)

### 🗃️ 保存された情報

- 設定フォーマットのバージョン
- アクティブ `current_profile`
- API キーとサーバー URL を使用した名前付きプロファイル

## トラブルシューティング

### ❌「APIキーが無効です」エラー

- **確認:** API キーが正しく、取り消されていないことを確認してください。
- **確認:** API キーの形式は `sk-` で始まる必要があります
- **紛失したキー:** ScaleBox は完全なシークレットを再度表示できません。[ダッシュボード](https://www.scalebox.dev/dashboard)すぐにコピーまたはダウンロードしてください
- **無効な CLI トークン:** `scalebox-cli auth login` を再度実行して、ブラウザーが発行したアクティブなプロファイルの `sb-cli-...` 資格情報を更新してください。

### ❌「接続が拒否されました」エラー

- **確認:** サーバー URL が正しいことを確認してください (https://api.scalebox.dev)
- **ネットワーク:** インターネット接続があることを確認してください
- **ファイアウォール:** HTTPS トラフィック (ポート 443) が許可されていることを確認してください

### ❌ 操作の「許可が拒否されました」

- **ユーザー キー:** API キーに必要な権限があることを確認してください
- **解決策:** アクセスするにはアカウント管理者にお問い合わせください。
- **確認:** `scalebox-cli auth whoami` を実行してロールを確認してください

### ❌ 設定ファイルの問題

- **リセット:** `scalebox-cli auth logout` を実行して、再度ログインします。
- **手動クリーンアップ:** `~/.scalebox-cli/config.json` を削除します
- **権限:** ファイル権限で読み取り/書き込みアクセスが許可されていることを確認してください

## セキュリティのベストプラクティス

### ✅ する

- API キーを安全に保管し、決して共有しないでください
- 操作には適切な API キーを使用してください
- API キーを定期的にローテーションします。
- 共有システムでの作業が終了したらログアウトします
- 信頼されたネットワークで CLI を使用する

### ❌ しないでください

- API キーをバージョン管理システムに保存する
- チャット、電子メール、またはドキュメントで API キーを共有する
- 許可レベルを超えて API キーを使用する
- 公共/共有コンピュータでは認証をアクティブのままにしておきます
- 権限エラーを無視します - 権限エラーはセキュリティ境界を示します
