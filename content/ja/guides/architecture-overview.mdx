## 使用しているもの

ScaleBox は **分離された サンドボックス 環境**を提供します。各 サンドボックス には、CPU、メモリ、ストレージ、ネットワーキング、および公開ポート、WebRTC、構成可能な出力動作などのオプション機能が定義されています。基礎となるオーケストレーションの概念ではなく、テンプレート、プロジェクト、ユーザー向けインターフェイスを介して サンドボックス を操作します。 **コントロール プレーン** (REST API、永続性、スケジューリング、および請求) はリクエストを受信し、サンドボックス をプロビジョニングし、そのライフサイクルと使用状況を追跡します。

アーキテクチャ上の重要な点は、ScaleBox が **1 つの サンドボックス エンジン**を中心に構築されているが、**Web コンソール**、**HTTP API**、**CLI**、**SDK** という **4 つのユーザー向けパス**を公開していることです。この製品は、ユーザーがワークフローの途中でサーフェスを切り替える必要がないように、各パスを可能な限りエンドツーエンドに維持しようとします。

## コントロール プレーンと サンドボックス

- **コントロール プレーン** — ScaleBox バックエンドは、バージョン管理された HTTP ルート (たとえば、`/v1/...` の下) を公開し、リクエストを認証し (通常は API キーを使用)、テンプレート、プロジェクト、サンドボックス、を調整します。ネットワーキング、アーカイブ、請求、および関連する操作。これはライフサイクルとメタデータの権限です。
- **サンドボックス ランタイム** - 実行中の各 サンドボックス は、柔軟なワークロード環境です。 サンドボックス エージェント、ユーザー プロセス、ノートブック カーネル、カスタム Web サービス、TCP サービス、WebRTC エンドポイント、および テンプレート およびランタイム構成によって定義されるその他のアプリケーション固有のワークロードをホストできます。

すべてのユーザー向けツールは最終的に **同じ** コントロール プレーンに依存しますが、ワークフローに応じて異なる方法で実行中の サンドボックス と対話する場合があります。

## Webコンソール（ダッシュボード）

**コンソール**は組織のブラウザ UI です。サインイン、API キー、テンプレート、サンドボックス のリストと詳細、使用状況と請求ビュー、および API の機能を反映する対話型フローが含まれます。

**最適な用途:** 検出、コードを書かずに日常的な操作、API キーの発行とローテーション、GUI を好むチームメイトとのコンテキストの共有。

**API との関係:** コンソールは、API がサービスを提供するのと同じバックエンドのクライアントです。 UI で実行できることにはすべて、対応する API 概念 (サンドボックス、テンプレート、キーなど) があり、以下に文書化されています。[API リファレンス](/ja/api/).

## HTTP API

**REST API** は自動化と統合のための契約です。 API キー (`X-API-Key` などのヘッダー) を使用して HTTPS リクエストを送信できる言語またはツールから使用してください。これは、コントロール プレーンの操作を直接カバーし、また、ファイル処理、端末アクセス、コマンド実行などの選択された低レベルの サンドボックス 操作をプロキシするので、API ファースト ユーザーが可能な限り 1 つのパスにとどまることができます。

**最適な用途:** CI/CD、カスタム内部ツール、オンデマンドで サンドボックス を作成および管理するサービス、およびほとんどの操作に 1 つの安定したバックエンド パスが必要な統合。

**他のツールとの関係:** CLI および SDK はこれらのエンドポイントを呼び出します。それらは別個の製品表面ではありません。ルートレベルの詳細については、を参照してください。[API リファレンス](/ja/api/).

## CLI (`scalebox-cli`)

**CLI** は、ほとんどのパブリック バックエンド機能をコマンド (認証、サンドボックス、テンプレート、プロジェクト、API キー、通知、Webhook、使用状況、請求など) としてパッケージ化します。 サンドボックス の場合、作成/リスト/接続フローだけでなく、`sandbox exec` などのファイル指向およびコマンド指向のワークフロー、さらに互換性のある テンプレート 上の高度な `sandbox run-code` フローもカバーされています。資格情報をローカル (たとえば、`~/.scalebox-cli/` の下) に保存し、選択した API ベース URL をターゲットにします。

**最適な用途:** SDK の依存関係を維持せずに、読み取り可能なコマンドと JSON 出力を必要とするターミナルファーストのワークフロー、スクリプト、およびオペレーター。

**API との関係:** CLI はコントロール プレーン タスクにバックエンドを使用しますが、多くのサンドボックス内操作では、サンドボックス固有の資格情報を使用して サンドボックス ドメインに直接接続することもできます。これにより、同じ製品モデルに適合しながら、より完全なエンドツーエンドの端末ワークフローが実現します。参照[CLI リファレンス](/ja/cli/)インストール、認証、およびコマンドのトピックについては、

## SDK (Python、JavaScript、Go、…)

公式 **SDK** は、言語の慣用的な型、ヘルパー、エラー処理で HTTP API をラップします。これらは個別のリポジトリとして配布されます (たとえば、Python、JavaScript、およびドキュメント ホームからリンクされた Go クライアント)。

**最適な用途:** 製品ロジックの一部として サンドボックス を管理する、存続期間の長いアプリケーション、エージェント、ノートブック、およびバックエンド。

**API との関係:** SDK は同じ REST API に対して維持されますが、CLI と同様に、バックエンドが `sandbox_domain` やサンドボックス スコープなどのランタイム接続の詳細を返した後、直接サンドボックス ドメイン アクセスに切り替わることもあります。トークン。

**アーキテクチャの概要**

`Web console / CLI / SDK / custom HTTP` → `backend control plane` → `sandbox created and exposed` → `backend-proxied access and/or direct sandbox-domain access`

|動作エリア |メインパス |内容 |
|---|---|---|
|コントロールプレーンの操作 |クライアント → バックエンド |認証、テンプレート、プロジェクト、作成、一時停止、再開、終了、リソース管理、使用状況、請求 |
|バックエンドプロキシによる低レベルの操作 |クライアント → バックエンド → サンドボックス |ファイル処理、ターミナル アクセス、実行、ストリーム/監視/キャンセル フロー、および 1 つのインターフェイスに留まるユーザー向けの同様のエンドツーエンド パス |
|ランタイムの直接対話 |クライアント → サンドボックス ドメイン |公開ポート上のカスタム サービス、直接 HTTP/WebSocket アクセス、TCP/TLS サービス、WebRTC エンドポイント、およびその他のサンドボックスでホストされるワークロード |
|サンドボックス エージェントの機能 |直接またはプロキシ |ファイルシステム操作、プロセス/PTY アクセス、コマンド実行、監視/ストリーム フロー、およびテンプレート依存の `run-code` / 実行コンテキスト機能 |

一般的なフロー:

1. **認証**します (コンソール セッションまたは CLI/SDK/API の API キー)。
2. **テンプレート** を定義し、適合するサーフェス (コンソールのクリック パス、`scalebox-cli sandbox create`、SDK 呼び出し、または `POST` から API) を通じて **サンドボックス** を作成します。
3. コントロール プレーンは、サンドボックス を **プロビジョニングして実行**します。 API/CLI/SDK 経由でステータスを **ポーリングまたはストリーミング**するか、コンソールを監視します。
4. 次に、必要なインターフェイスとランタイム機能に応じて、バックエンド プロキシ操作を通じて、または サンドボックス ドメインに直接接続して、**実行中の サンドボックス を操作します**。

サーフェスは**構成可能**です。多くのチームは、キーと可視性のためにコンソールを使用し、ローカル反復には CLI を、生産自動化には API または SDK を使用します。

## はじめに

1. **アカウント** — ScaleBox インスタンスにサインアップし、[ダッシュボード](https://www.scalebox.dev/dashboard)**API キー**を作成またはコピーします。
2. **サーフェスを選択** —[CLI クイック スタート](/ja/cli/quick-start)端末セットアップの場合、または上のリンクから SDK を選択します。[ガイドの概要](/ja/guides)、または次を使用して API を直接呼び出します。[API リファレンス](/ja/api/).
3. **サンドボックス の作成** — パブリック テンプレート から開始し、ガイドと CLI/API ドキュメントでポート、ライフサイクル、および高度なトピックを調べます。

サンドボックス 内の WebRTC の機能に重点を置いたチュートリアルについては、を参照してください。[WebRTC の サンドボックス](/ja/guides/webrtc-in-sandboxes).
