# Webhooks API

ScaleBox Webhooks 允许您在账户中发生事件时接收实时通知。
无需轮询 API，Webhook 会自动将事件推送到您的端点，减少 API 调用并提供近乎即时的通知。

## Webhook 概念

Webhook 是 HTTP 回调，当 ScaleBox 中发生事件时会通知您的应用程序。
无需持续轮询 API 来检查状态变化，Webhook 会自动将事件推送到您的端点。

### Webhook 工作原理

1. **事件发生** - 沙盒启动、终止或账户中发生其他事件
2. **Webhook 检测** - ScaleBox 检测到事件并找到匹配的 Webhook 端点（5 秒内）
3. **HTTP POST 交付** - ScaleBox 向您的 Webhook URL 发送包含事件数据的 HTTP POST 请求
4. **您的端点响应** - 您的端点处理 Webhook 并返回 HTTP 200 OK（失败时重试）

### Webhook 的优势

- **减少 API 调用** - 无需轮询 - 事件自动推送（API 调用减少 99%+）
- **实时通知** - 事件发生后 5 秒内接收通知
- **事件驱动架构** - 完美适用于自动化、CI/CD 管道和 AI 代理
- **自动重试** - 失败的交付会自动重试，采用指数退避策略

## API 端点

### create-webhook

**POST** `/v1/webhooks`

创建新的 Webhook 端点以接收事件通知

#### 请求参数

| 参数 | 类型 | 必需 | 描述 |
|------|------|------|------|
| url | string | 是 | 接收 Webhook 的 HTTPS URL |
| event_types | array[string] | 是 | 要订阅的事件类型数组（例如：`['sandbox.started', 'sandbox.terminated']`） |
| description | string | 否 | Webhook 端点的可选描述 |

#### 请求示例

```bash
curl -X POST https://api.scalebox.dev/v1/webhooks \
  -H "X-API-Key: sk-1234567890abcdef1234567890abcdef12345678" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://your-app.com/webhooks/scalebox",
    "event_types": ["sandbox.started", "sandbox.terminated"],
    "description": "生产环境沙盒生命周期事件 Webhook"
  }'
```

#### 响应示例

```json
{
  "success": true,
  "data": {
    "endpoint_id": "whk-abc123def456789",
    "url": "https://your-app.com/webhooks/scalebox",
    "event_types": ["sandbox.started", "sandbox.terminated"],
    "is_active": true,
    "description": "生产环境沙盒生命周期事件 Webhook",
    "timeout_seconds": 30,
    "max_retries": 3,
    "created_at": "2024-01-15T10:30:00Z",
    "updated_at": "2024-01-15T10:30:00Z"
  }
}
```

### update-webhook

**PUT** `/v1/webhooks/{endpoint_id}`

更新 Webhook 端点配置（URL、事件类型、状态）

#### 请求参数

| 参数 | 类型 | 必需 | 默认值 | 描述 |
|------|------|------|--------|------|
| url | string | 否 | - | 新的 Webhook 交付 URL |
| event_types | array[string] | 否 | - | 更新的订阅事件类型列表 |
| is_active | boolean | 否 | - | 启用或禁用 Webhook 端点 |
| description | string | 否 | - | 更新的描述 |
| timeout_seconds | integer | 否 | 30 | HTTP 请求超时时间（5-300 秒） |
| max_retries | integer | 否 | 3 | 最大重试次数（0-10） |

#### 请求示例

```bash
curl -X PUT https://api.scalebox.dev/v1/webhooks/whk-abc123def456789 \
  -H "X-API-Key: sk-1234567890abcdef1234567890abcdef12345678" \
  -H "Content-Type: application/json" \
  -d '{
    "is_active": false,
    "event_types": ["sandbox.started", "sandbox.terminated", "sandbox.failed"]
  }'
```

## 事件类型

ScaleBox 发出各种事件类型，您可以通过 Webhook 订阅。
每个事件类型代表系统中的特定状态变化或操作。

| 事件类型 | 描述 |
|----------|------|
| sandbox.created | 沙盒创建时触发（尚未运行） |
| sandbox.started | 沙盒开始运行并准备就绪时触发 |
| sandbox.stopped | 沙盒停止时触发（退出运行状态） |
| sandbox.paused | 沙盒暂停时触发（CPU/内存计费停止） |
| sandbox.resumed | 沙盒恢复时触发（CPU/内存计费恢复） |
| sandbox.terminated | 沙盒完全终止并清理时触发 |
| sandbox.failed | 沙盒启动失败或崩溃时触发 |
| template.uploaded | 模板镜像上传到 Harbor 时触发 |
| template.deleted | 模板删除时触发 |

## Webhook 负载

所有 Webhook 交付都包含一致的 JSON 负载结构：

```json
{
  "id": "evt-abc123def456789",
  "type": "sandbox.started",
  "timestamp": "2024-01-15T10:30:00Z",
  "data": {
    "sandbox_id": "sbx-xyz789abc123456",
    "status": "running",
    "cpu_count": 2,
    "memory_mb": 4096,
    "storage_gb": 20,
    "template_id": "tpl-python-3.11",
    "project_id": "prj-abc123def456789",
    "owner_user_id": "usr-xyz789abc123456",
    "owner_account_id": "acc-123456789",
    "kubernetes_metadata": {
      "cluster_id": "cls-abc123",
      "namespace_id": "ns-xyz789",
      "pod_name": "sbx-xyz789abc123456",
      "pod_ip": "10.0.0.5",
      "node_name": "worker-node-1"
    }
  }
}
```

### 负载字段

- `id` - 唯一事件标识符 (evt-xxxxx)
- `type` - 事件类型（例如："sandbox.started"）
- `timestamp` - 事件发生时的 ISO 8601 时间戳
- `data` - 特定于事件的数据对象（因事件类型而异）

## 安全与验证

所有 Webhook 交付都包含 HMAC-SHA256 签名，您可以使用它来验证请求的真实性。
这可以防止篡改并确保 Webhook 来自 ScaleBox。

### HTTP 请求头

| 请求头 | 描述 |
|--------|------|
| X-ScaleBox-Signature | 负载的 HMAC-SHA256 签名 |
| X-ScaleBox-Event-Type | 事件类型（例如："sandbox.started"） |
| X-ScaleBox-Event-ID | 唯一事件标识符 |
| Content-Type | application/json |
| User-Agent | ScaleBox-Webhooks/1.0 |

### 签名验证示例

**Python**

```python
import hmac
import hashlib

def verify_webhook_signature(payload_body, signature_header, secret):
    """验证 Webhook 签名"""
    expected_signature = hmac.new(
        secret.encode('utf-8'),
        payload_body.encode('utf-8'),
        hashlib.sha256
    ).hexdigest()
    
    received_signature = signature_header.replace('sha256=', '')
    return hmac.compare_digest(expected_signature, received_signature)
```

**Node.js**

```javascript
const crypto = require('crypto');

function verifyWebhookSignature(payloadBody, signatureHeader, secret) {
  const expectedSignature = crypto
    .createHmac('sha256', secret)
    .update(payloadBody)
    .digest('hex');
  
  const receivedSignature = signatureHeader.replace('sha256=', '');
  return crypto.timingSafeEqual(
    Buffer.from(expectedSignature),
    Buffer.from(receivedSignature)
  );
}
```

<Callout type="warn">
**重要：密钥存储**

Webhook 密钥在创建端点时生成，永远不会在 API 响应中暴露。
您必须安全地存储此密钥以验证传入的 Webhook。如果丢失密钥，
您需要删除并重新创建 Webhook 端点。
</Callout>

## 重试机制

ScaleBox 自动重试失败的 Webhook 交付以确保可靠性。
失败的交付会使用指数退避策略进行重试。

### 重试行为

- **自动重试** - 失败的交付（非 2xx HTTP 状态码）会自动重试
- **指数退避** - 重试间隔：2 分钟、4 分钟、6 分钟（可配置倍数）
- **最大尝试次数** - 默认：3 次尝试（每个端点可配置，0-10）
- **交付状态** - `pending` → `retrying` → `delivered` 或 `failed`

## 最佳实践

- **使用 HTTPS URL** - 始终使用 HTTPS 作为 Webhook 端点以确保安全交付
- **验证签名** - 始终验证 X-ScaleBox-Signature 请求头以确保 Webhook 的真实性
- **快速响应** - 在 30 秒内返回 HTTP 200 OK 以避免超时
- **幂等处理** - 使用事件 ID 防止在 Webhook 重试时重复处理
- **监控交付历史** - 定期检查交付历史以识别和修复端点问题
