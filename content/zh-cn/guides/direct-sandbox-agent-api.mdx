<Callout type="info">
当你想在沙箱已经创建完成后，直接与**运行中的沙箱**交互时，请使用本指南。后端仍然是沙箱生命周期与元数据的控制平面，而 sandbox agent 则是暴露在 sandbox domain 上的运行时 API。
</Callout>

<Callout type="warn">
只要条件允许，我们都强烈建议你优先使用官方 **Python**、**Go** 或 **JavaScript** SDK 来做正式集成。它们已经封装了 sandbox-domain 鉴权、ConnectRPC 调用模式、流式处理与错误处理。raw sandbox-agent HTTP 或 ConnectRPC 调用更适合作为高级、底层路径使用。
</Callout>

官方 SDK 直达链接：

- [Python SDK 仓库](https://github.com/scalebox-dev/scalebox-sdk-python)
- [JavaScript SDK 仓库](https://github.com/scalebox-dev/scalebox-sdk-js)
- [Go SDK 仓库](https://github.com/scalebox-dev/scalebox-sdk-golang)

## 这条路径是什么

当你通过 ScaleBox 后端创建或查询沙箱后，响应中可能包含：

- `sandbox_domain` - 沙箱的直接运行时域名
- `envd_access_token` - 为该沙箱生成的沙箱级访问令牌

这个 `envd_access_token` 就是 sandbox agent 期望接收的 `X-Access-Token` 头值。对 direct agent call 而言，`Authorization` 头当前固定为 `Bearer root`。

CLI 与各类 SDK 在很多沙箱内操作中，走的也是这条直接运行时路径。

## 什么时候使用

当你需要以下能力时，适合直接调用 sandbox-agent API：

- 直接对 sandbox domain 进行文件上传与下载
- 不经过后端，直接做进程与 PTY 控制
- 在兼容模板上执行代码与执行上下文相关流程
- 构建一个更贴近沙箱运行时本身的集成

当你需要创建、列表、查询、暂停、恢复、终止、模板、项目、用量、计费等控制平面操作时，应继续使用后端 API。

## 前置条件

1. 先通过后端 API、CLI 或 SDK 创建或查询一个沙箱。
2. 从沙箱对象中读取 `sandbox_domain`。
3. 从同一个沙箱对象中读取 `envd_access_token`。

后端返回的相关字段示例：

```json
{
  "sandbox_id": "sbx-abc123def456789",
  "sandbox_domain": "sbx-abc123def456789.example.scalebox.dev",
  "envd_access_token": "envd-abc123def456789"
}
```

## 基础 URL 与认证

进行 direct call 时，直接把 sandbox domain 当作主机名：

```bash
export SANDBOX_DOMAIN="sbx-abc123def456789.example.scalebox.dev"
export ENVD_ACCESS_TOKEN="envd-abc123def456789"
```

对大多数 sandbox-agent 请求，发送以下头：

```http
Authorization: Bearer root
X-Access-Token: <envd_access_token>
```

示例：

```bash
curl -X GET "https://${SANDBOX_DOMAIN}/health"
```

```bash
curl -X POST "https://${SANDBOX_DOMAIN}/sandboxagent.ContextService/CreateContext" \
  -H "Authorization: Bearer root" \
  -H "X-Access-Token: ${ENVD_ACCESS_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"language":"python","cwd":"/home/user"}'
```

## 认证模型

这里有两种认证方式：

| 路径类型 | 认证方式 | 说明 |
|---|---|---|
| 大多数 sandbox-agent 端点 | `Authorization: Bearer root` + `X-Access-Token` | ConnectRPC procedure 与普通 HTTP 端点的标准直连方式 |
| `/upload` 与 `/download/...` | 同样的 headers，或签名 URL 查询参数 | 适用于有时效性的委托式文件访问 |

对大多数用户而言，直接使用 header 认证是最简单的方式。

## 端点总览

当前 raw sandbox-agent 对外暴露 **22 个可通过 HTTP 调用的端点**：

- **3 个普通 HTTP 端点**
- **19 个 ConnectRPC procedure 端点**

### 普通 HTTP 端点

| Method | Path | Auth | 说明 |
|---|---|---|---|
| `GET` | `/health` | 无 | 简单健康检查，返回 `OK` |
| `POST` | `/upload` | headers 或 signed URL | multipart 上传端点 |
| `GET` | `/download/{path}` | headers 或 signed URL | 文件下载端点，支持 Range |

### ConnectRPC 端点

剩余端点都是 procedure 风格的 HTTP 路径。Unary procedure 可以通过 HTTP `POST` + JSON 调用。Streaming procedure 更适合通过 CLI、SDK 或 ConnectRPC 客户端调用。

#### Filesystem 服务

| Procedure path | 类型 | 用途 |
|---|---|---|
| `/sandboxagent.Filesystem/Stat` | unary | 查询文件或目录信息 |
| `/sandboxagent.Filesystem/MakeDir` | unary | 创建目录 |
| `/sandboxagent.Filesystem/Move` | unary | 移动或重命名路径 |
| `/sandboxagent.Filesystem/ListDir` | unary | 列出目录内容 |
| `/sandboxagent.Filesystem/Remove` | unary | 删除文件或目录 |
| `/sandboxagent.Filesystem/CreateWatcher` | unary | 创建 watcher 并返回 `watcher_id` |
| `/sandboxagent.Filesystem/GetWatcherEvents` | unary | 轮询 watcher 事件 |
| `/sandboxagent.Filesystem/RemoveWatcher` | unary | 删除 watcher |
| `/sandboxagent.Filesystem/WatchDir` | server stream | 直接流式接收文件系统事件 |

#### Process 服务

| Procedure path | 类型 | 用途 |
|---|---|---|
| `/sandboxagent.Process/List` | unary | 列出已跟踪的进程 |
| `/sandboxagent.Process/Connect` | server stream | 连接到已有进程或 PTY |
| `/sandboxagent.Process/Start` | server stream | 启动进程并流式接收输出 |
| `/sandboxagent.Process/Update` | unary | 更新进程状态，例如 PTY 尺寸 |
| `/sandboxagent.Process/StreamInput` | client stream | 流式发送 stdin 或 PTY 输入 |
| `/sandboxagent.Process/SendInput` | unary | 发送一次输入 |
| `/sandboxagent.Process/SendSignal` | unary | 发送 `SIGTERM` 或 `SIGKILL` |

#### Execution 与 Context 服务

| Procedure path | 类型 | 用途 |
|---|---|---|
| `/sandboxagent.ExecutionService/Execute` | server stream | 执行代码并流式返回输出与结果 |
| `/sandboxagent.ContextService/CreateContext` | unary | 创建执行上下文 |
| `/sandboxagent.ContextService/DestroyContext` | unary | 销毁执行上下文 |

## 普通 HTTP 示例

### 健康检查

```bash
curl "https://${SANDBOX_DOMAIN}/health"
```

### 上传文件

上传接口要求 `multipart/form-data`，并包含：

- 一个 `file` part
- 一个 `path` 表单字段，表示目标路径

```bash
curl -X POST "https://${SANDBOX_DOMAIN}/upload" \
  -H "Authorization: Bearer root" \
  -H "X-Access-Token: ${ENVD_ACCESS_TOKEN}" \
  -F "file=@./script.py" \
  -F "path=/tmp/script.py"
```

### 下载文件

```bash
curl -L "https://${SANDBOX_DOMAIN}/download/tmp/script.py" \
  -H "Authorization: Bearer root" \
  -H "X-Access-Token: ${ENVD_ACCESS_TOKEN}" \
  -o ./script.py
```

下载接口还支持 `Range` 请求，适合断点续传或部分下载。

## Unary ConnectRPC 示例

### 创建执行上下文

```bash
curl -X POST "https://${SANDBOX_DOMAIN}/sandboxagent.ContextService/CreateContext" \
  -H "Authorization: Bearer root" \
  -H "X-Access-Token: ${ENVD_ACCESS_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "language": "python",
    "cwd": "/home/user"
  }'
```

### 列出目录

```bash
curl -X POST "https://${SANDBOX_DOMAIN}/sandboxagent.Filesystem/ListDir" \
  -H "Authorization: Bearer root" \
  -H "X-Access-Token: ${ENVD_ACCESS_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "path": "/tmp",
    "depth": 1
  }'
```

### 查询路径信息

```bash
curl -X POST "https://${SANDBOX_DOMAIN}/sandboxagent.Filesystem/Stat" \
  -H "Authorization: Bearer root" \
  -H "X-Access-Token: ${ENVD_ACCESS_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "path": "/tmp/script.py"
  }'
```

## Streaming procedure

以下运行时操作是流式的：

- `Filesystem/WatchDir`
- `Process/Connect`
- `Process/Start`
- `Process/StreamInput`
- `ExecutionService/Execute`

这些接口依然是 HTTP 可调用的，但通常更适合通过以下方式使用：

- `scalebox-cli`
- 官方 SDK
- 你自己的 ConnectRPC 客户端程序

如果你的目标是终端交互、文件监听、实时进程输出或流式代码执行，CLI 或 SDK 往往是更好的接口。

## Signed URL 文件访问

`/upload` 与 `/download/...` 也支持使用签名查询参数，而不是直接传递认证头。这适合做临时、受限的文件访问授权。

但对大多数集成而言，直接 header 认证仍然更简单、更容易理解。

## 它与 SDK 的关系

SDK 本质上封装的就是同一条运行时路径：

- 从后端沙箱响应中读取 `sandbox_domain` 与 `envd_access_token`
- 设置 `Authorization: Bearer root`
- 设置 `X-Access-Token: <envd_access_token>`
- 调用本文展示的同一批 sandbox-domain 端点

这意味着你可以先使用 SDK，之后在需要更底层控制时再下沉到 raw HTTP。
